## Project Overview

This is a custom Shopify theme ("Eazy Ayurveda") built on top of Shopify's **Horizon theme v3.2.1**. There is no build step — all files are native Shopify Liquid, JavaScript, and CSS pushed directly to Shopify via the Shopify CLI.

## Development Commands

```sh
# Authenticate with Shopify
shopify auth login

# Push theme to store (development)
shopify theme push --store <store-url>

# Pull latest from live theme
shopify theme pull --store <store-url>

# Start local dev server (hot-reload via proxy)
shopify theme dev --store <store-url>

# Check theme for errors
shopify theme check
```

## Architecture

### Rendering Pipeline

`layout/theme.liquid` is the root HTML document. It renders section groups for header/footer:
```liquid
{% sections 'header-group' %}  {# → sections/header-group.json #}
{% sections 'footer-group' %}  {# → sections/footer-group.json #}
{% section 'content' %}        {# injected by template #}
```

Templates in `templates/` are JSON files that declare which sections appear on each page type. Sections in `sections/` are the building blocks; they declare which block types they accept. Blocks in `blocks/` are sub-components rendered inside sections. Snippets in `snippets/` are stateless partials rendered via `{% render 'snippet-name' %}`.

### JavaScript: Web Components

All interactive UI is implemented as **custom HTML elements** extending a shared `Component` base class (`assets/component.js`). Every component:
- Extends `Component` (which extends `DeclarativeShadowElement`)
- Declares `refs = {}` — automatically populated from DOM elements with `[ref]` attributes
- Lists `requiredRefs = []` for validation on init
- Is registered via `customElements.define('element-name', ClassName)`

Key utilities in `assets/utilities.js`:
- `requestIdleCallback` with `setTimeout` fallback
- `yieldToMainThread()` using `scheduler.yield()` for long-task splitting
- `isLowPowerDevice()` — checks `navigator.deviceMemory < 4`
- View Transitions API helpers

Custom events flow through `assets/events.js`.

### CSS: Custom Properties

`assets/base.css` drives all theming via CSS custom properties (e.g. `--color-foreground`, `--hover-lift-amount`). Color schemes are generated dynamically via `snippets/color-schemes.liquid` and injected as scoped CSS variable overrides. Never hardcode colors — always use the existing custom property system.

### Settings & Configuration

- `config/settings_schema.json` — defines all theme-wide settings shown in the Shopify Customizer
- `config/settings_data.json` — stores the active saved values (do not edit manually; use the Customizer or CLI pull)

### Localization

Translation strings live in `locales/`. The default is `locales/en.default.json`. Schema translations (settings labels) are in `locales/xx.schema.json` files. Use `{{ 'key' | t }}` in Liquid to reference translations.

## Key Conventions

- **Blocks** are prefixed with `_` (e.g. `blocks/_product-card-gallery.liquid`) to distinguish them from sections.
- **Templates** are JSON and auto-generated by the Shopify editor — edits in the Customizer overwrite them. Edit section/block Liquid directly instead.
- **TypeScript checking** is enabled via `assets/jsconfig.json` (`checkJs: true`, target ES2020). Use JSDoc types; global Shopify API types are in `assets/global.d.ts`. The `@theme/*` path alias maps to `assets/`.
- **No minification** happens locally — Shopify CDN handles optimization.
- When adding a new interactive component, follow the pattern: create `assets/component-name.js`, define a custom element class extending `Component`, register with `customElements.define`, and load the script in the relevant section/snippet Liquid file.
